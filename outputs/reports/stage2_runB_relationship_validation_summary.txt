STAGE 2 RUN B -- RELATIONSHIP VALIDATION ENGINE
==================================================================

AUDIT UPDATE (post-freeze correction): a methodology audit of this engine
found that all permutation nulls used a FLAT row-level shuffle of the
target, which does not preserve LotName-block structure the way every
other part of this engine's validation does. This was corrected to a
GROUP-BLOCK shuffle (src/explain/stage2_relval_common.py::
group_block_shuffle -- reassigns each lot's intact y-block to a different
lot, preserving within- and between-lot variance while destroying the X-Y
association) and every downstream file (single/2way/triple_screen/3way/
fdr/negative_control) was rerun. The correction moved the null slightly
more conservative in every family (fewer FDR survivors, e.g. single-
parameter 1,109->1,048) but changed no headline conclusion: the same top
findings recur, and the calibration gate still PASSES cleanly. All numbers
below reflect the CORRECTED, current frozen outputs. See the dedicated
audit report for full detail: stage2_runB_relval_methodology_audit.txt (or
.md, per final filename).

Purpose: a new, complementary Stage 2 component whose goal is to
VALIDATE (not merely discover) single-parameter, 2-way, and 3-way
relationships, using genuine permutation-based empirical significance
testing and Benjamini-Hochberg false-discovery-rate (FDR) control as the
primary acceptance gate -- on top of, not instead of, LotName-grouped
5-fold cross-validated stability. This is NOT a predictive model. No
existing Stage 1 or Stage 2 method, threshold, or output was modified.
Ground-truth document was not read anywhere in this pipeline; no known
planted parameter name was hard-coded, forced into any candidate pool, or
used to tune any threshold.

METHOD -- WHAT IS REUSED vs. WHAT IS NEW
------------------------------------------------------------------
REUSED, UNMODIFIED: the spline/GAM nonlinear-fitting machinery (fit_linear,
fit_spline, classify_curve_shape from the spline checkpoint -- "an
existing lightweight nonlinear method already available in the project,"
per instruction, explicitly NOT a neural network); the additive-vs-joint
2-way and lower-order-vs-full 3-way binned-model machinery (fit_additive_
joint, fit_threeway and their predict_* functions from the v3 checkpoint);
the exhaustive vectorized broad pair-screen scores (v2's marginal-residual
proxy and v3's 2D-binned non-additivity energy).

NEW in this checkpoint (present nowhere in any prior Stage 2 checkpoint):
genuine PERMUTATION-BASED EMPIRICAL P-VALUES -- for each family (single-
parameter, 2-way, 3-way), a pooled null distribution of the test statistic
(incremental R^2) is built from B target-label shuffles applied to the
SAME candidates as the real analysis (B=8 for single-parameter, B=10 for
2-way and 3-way -- disclosed, generic choices, not ground-truth-tuned),
and a from-scratch BENJAMINI-HOCHBERG FDR procedure (implemented with
plain numpy, verified against the textbook 5-p-value example before use)
is applied to determine which findings survive at alpha=0.05. FDR survival
is a REQUIRED, not optional, component of every STRONG/MODERATE label in
this engine -- a relationship failing FDR is always labeled INCONCLUSIVE
regardless of its raw fold-consistency, which is a materially stricter bar
than every prior Stage 2 checkpoint used.

------------------------------------------------------------------
8. GROUPED-FOLD STABILITY FRAMEWORK (AS USED, DOCUMENTED)
------------------------------------------------------------------
STRONG   = 5/5 grouped folds improved AND effect size exceeds the
           family's own empirical-null 95th percentile AND survives FDR.
MODERATE = 4/5 grouped folds improved AND the same two conditions.
WEAK     = >=2 folds improved or effect exceeds the null threshold, but
           not both, and/or fails the stricter STRONG/MODERATE bar.
INCONCLUSIVE = fails FDR (checked FIRST, unconditionally), OR unstable/
           negligible under the above.
This is the thresholds framework proposed in the checkpoint instructions,
used AS-IS -- the empirical null (not an arbitrary constant) supplies the
"meaningful effect size" component, which is the recalibration the
instructions explicitly permitted ("do not use these thresholds blindly
if the empirical null suggests a better calibration"); the fold-count
cutoffs (5/5, 4/5) were used exactly as proposed, unmodified.

11. RUNTIME AND COMPUTATIONAL COMPROMISES
------------------------------------------------------------------
Total script runtime across all stages: approximately 15 minutes
(pair broad-screen ~10s; single-parameter real+null ~171s; 2-way
real+null ~170s; triple screen ~30-60s; 3-way real+null ~384s; FDR
consolidation <5s; negative control ~66s).

Computational compromises (all disclosed above, not silent):
- 2-way and 3-way candidate generation are NECESSARILY selective, not
  exhaustive (986,310 -> 6,677 promoted pairs; 461M theoretical -> 13,064
  generated triples) -- exhaustive expensive validation at either scale is
  combinatorially infeasible, consistent with every prior Stage 2
  interaction checkpoint in this project.
- Every promotion/generation channel is individually capped at a
  disclosed, round-number, non-ground-truth-tuned size (2,000 / 1,000 /
  600 / 155 / etc.) -- a real relationship whose evidence falls just
  outside a channel's own cap will not be tested this checkpoint.
- Permutation null sizes (B=8 for single-parameter, B=10 for 2-way/3-way)
  give an empirical p-value resolution floor of roughly 1/(n_null+1) --
  e.g. ~0.00014 for single-parameter, ~0.000015 for 2-way/3-way -- fine
  for the ranks that matter under BH at these family sizes, but truly
  vanishing effects cannot be distinguished from each other below that
  floor.
- The negative-control PASS/FAIL gate (section 7) used ONE additional
  fresh permutation per family (not the full B-permutation pool) for the
  fold-stability-distribution comparison, to keep the gate check itself
  cheap; the pooled-null EFFECT-SIZE distributions it also reports DO use
  the full B-permutation pools already computed for FDR.

12. KNOWN LIMITATIONS
------------------------------------------------------------------
- This engine's candidate-generation channels are NOT identical to v3/v4/
  v5's -- some previously-important relationships (Rc x Rsh, Gate CD x
  SiN, the Rc/Drain-Lag/PAE triple) were not re-tested here because none
  of this engine's own 7 (pairs) / 5 (triples) channels happened to reach
  them, independent of and in addition to v4/v5's own prior coverage gaps
  on the same relationships.
- The BH-FDR procedure controls the EXPECTED PROPORTION of false
  discoveries among what is called significant -- it does not guarantee
  any single accepted finding is real, and with a heavily redundant
  feature universe (many ET/process columns are correlated proxies of a
  smaller number of true underlying drivers, as established throughout
  this project), a high overall confirmation rate is an expected property
  of the DATA's own correlation structure, not necessarily evidence of
  21,146 independent phenomena.
- Single-parameter and interaction shape/region characterization remains a
  MARGINAL (single/pairwise/triple-wise) analysis -- it does not control
  for the full set of other correlated predictors simultaneously.
- No sensitivity analysis was performed on the PASS_RATIO_THRESHOLD (25%)
  or the specific B_PERM values chosen -- these are disclosed, reasonable,
  round-number choices, not empirically optimized.
