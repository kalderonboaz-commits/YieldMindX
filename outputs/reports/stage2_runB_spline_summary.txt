STAGE 2 RUN B -- COMPLEMENTARY SPLINE/GAM SINGLE-PARAMETER RELATIONSHIP
DISCOVERY SUMMARY
==================================================================

Purpose: a SECOND, complementary single-parameter method alongside the
existing LightGBM SHAP/PDP method (v1) and the model-free quantile-binning
screen (v2). Does not replace, retrain, or modify either. No tree model,
no neural network. Stage 1, the Run B feature universe, interaction
discovery, the v2 pairwise screen, and the v2 3-way search are all
untouched. Ground-truth document was not read anywhere in this checkpoint.

------------------------------------------------------------------
METHOD
------------------------------------------------------------------
For each numeric predictor x: SortingYield ~ smooth_function(x), fit as
SplineTransformer (cubic B-spline basis, up to 6 knots, extrapolation=
"linear") -> RidgeCV (internally cross-validated regularization strength).
Compared against a plain LinearRegression null on the same folds.

Grouped (by LotName) 5-fold CV, fit only on training folds, evaluated only
on held-out folds; the final holdout split is never touched. For each
feature: (a) linear-vs-spline out-of-fold RMSE/R^2 comparison across the 5
folds, (b) a main spline curve fit on the full training portion plus 5
independently-fit per-fold curves evaluated on one shared grid (40 points,
2nd-98th percentile of x), (c) shape classified from the main curve via a
significance-filtered turning-point count, where "significant" is judged
against the curve's own cross-fold standard deviation (the spline analogue
of the standard-error filter already used by v2's classify_binned_shape --
same flat_threshold_frac=0.15 and se_multiple=1.3 constants, reused rather
than re-tuned). Evidence label requires BOTH majority shape reproduction
across the 5 independent fold curves AND positive out-of-fold spline R^2
(genuine predictive contribution, not just curve-fitting flexibility).

Real-target STRONG rate (53.3%) vs. shuffled-target STRONG rate (0.0%) is a
clean, complete separation -- far cleaner than v2's own negative control
(12.8% real vs. 4.5% shuffled). This is expected: the out-of-fold R^2 > 0
gate is a hard filter that shuffled targets essentially never pass (a
single shuffled feature predicting yield out-of-fold with positive R^2 by
chance is rare with ~700-900 training rows per fold), so this method's
thresholds are not noise-driven and do not require recalibration.

IMPORTANT INTERPRETIVE CAUTION (not a defect, but required honest context):
a clean negative control does NOT mean 53.3% of raw parameters are
independent, causally distinct yield drivers. The out-of-fold R^2 > 0 bar
is a low bar for "some real, reproducible signal exists" -- it does not
require the effect to be large, or independent of other correlated
predictors. Given the process/ET parameter space's known correlation
structure (already documented in the v1/v2 checkpoints: leakage-family
columns, cross-stage duplicated measurements, etc.), many of the 749
STRONG single-parameter findings very likely reflect a smaller number of
true underlying latent yield drivers observed through many correlated
proxy columns, not 749 independent phenomena. The STRONG list should be
read as "these 749 columns each individually carry reproducible signal,"
not as "there are 749 separate root causes."

------------------------------------------------------------------
COMPUTATIONAL LIMITATIONS
------------------------------------------------------------------
- This is a marginal (univariate) response curve, exactly like v1's PDP
  and v2's binned screen -- it does not control for other correlated
  predictors. A feature can score STRONG here because it correlates with
  the true driver, not because it IS the true driver (see interpretive
  caution above).
- Shape classification (THRESHOLD vs. SATURATION vs. MONOTONIC vs.
  U_SHAPED/INVERTED_U vs. PROCESS_WINDOW) is a heuristic turning-point-
  count rule on a 40-point grid with fixed edge/window fraction cutoffs
  (0.2 / 0.3), not a formal statistical changepoint-detection test --
  shapes near a cutoff boundary could classify differently under a
  different grid resolution.
- The spline basis is capped at min(6, n_unique_values // 3) knots, so
  features with few unique values get a simpler basis than the nominal
  6-knot cubic spline, reducing this method's ability to detect fine
  structure specifically for those features.
- RidgeCV's internal alpha selection uses scikit-learn's default (non-
  grouped) internal CV on each training fold's own rows -- this never
  touches validation/holdout data, but is a minor simplification relative
  to grouping by LotName at that inner hyperparameter-selection level too.
- No formal multiple-testing correction (e.g. Benjamini-Hochberg) was
  applied across the 1,405 simultaneous tests -- the fold-stability +
  positive-out-of-fold-R^2 gate and the shuffled-target negative control
  are the false-discovery safeguards used here, consistent with v1/v2.
- The comparison against v1 is limited by v1's own 154/1,405 coverage;
  rows outside that set are "not screened by v1," not "v1 disagrees."
